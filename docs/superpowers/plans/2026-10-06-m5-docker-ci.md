# M5 Docker and CI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command (`docker compose up`) starts the API and an MLflow server, and GitHub checks every push automatically (lint, tests, Docker build).

**Architecture:** The app image contains Python, the packages, the code and the embedding model. The search index is not in the image: it is mounted from `./data`, because it is built from the Bundestag API and is git-ignored. `docker-compose.yml` runs the app (port 8000) and MLflow (port 5000, showing the evaluation runs from M4). A GitHub Actions workflow runs ruff and pytest, and builds the image.

**Tech Stack:** Docker, Docker Compose, GitHub Actions, ruff.

**Spec:** `docs/superpowers/specs/2026-10-05-energiewende-agent-design.md` (section 7, milestone M5)

This is plan 5 of 6.

## Global Constraints

- Code style: as simple and plain as possible, short comments in simple English.
- The image never contains `.env`, keys, `data/` or MLflow runs (`.dockerignore`).
- PyTorch is installed from the CPU-only index (`https://download.pytorch.org/whl/cpu`), so the image has no GPU libraries.
- Tests in CI need no secrets and no network calls to LLMs or data APIs.
- Pinned: `ruff==0.16.10`; `actions/checkout@v7`, `actions/setup-python@v7`; MLflow image `ghcr.io/mlflow/mlflow:v3.16.1`.
- Every commit message ends with the line `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Verified facts these tasks rely on (checked 2026-10-06)

- Docker Desktop 29.8.2 with Compose v5.5.1, linux/arm64, 8 CPUs, 8 GB memory. The `docker` command lives in `~/.docker/bin` (add it to `PATH` if a shell does not find it).
- Docker Compose resolves `${OTHER_VAR}` inside an `env_file` (tested: `DERIVED=${BASE_TOKEN}` gave the value of `BASE_TOKEN`). So the `.env` line `LLM_API_KEY=${...}` works in the container.
- `ghcr.io/mlflow/mlflow:v3.16.1` exists for amd64 and arm64.
- The M4 MLflow runs store absolute artifact paths (`/Users/.../energiewende-agent/mlruns/1/...`). The MLflow container therefore mounts `./mlruns` at the same absolute path (`${PWD}/mlruns`), or the UI cannot show `questions.json`.
- All 50 tests pass with no `.env` and an empty environment (`env -i`), so CI needs no secrets.
- ruff 0.16 enables more rules by default than the classic set; with `select = ["E4", "E7", "E9", "F"]` the only finding is a real one: an unused `date` import in `src/energiewende/ingest/smard.py`.
- Latest action versions: `actions/checkout` v7.0.1, `actions/setup-python` v7.0.0.
- The GitHub repo `Omercan4/energiewende-agent` exists (private); `main` is pushed.
- Docker build with CPU torch and the model baked in: 2 min 40 s, image 3.25 GB, `torch 2.14.1+cpu`, no nvidia packages.
- macOS asks once whether Docker may read the Desktop folder; until that is allowed, `docker run -v ./data:...` hangs in state `Created`.
- **`docker run --env-file` does not resolve `${OTHER_VAR}`** (the container got the literal text `${...}` and the LLM answered 401). Compose does. So the `/ask` check runs with Compose in Task 3; Task 2 only checks `/health`.

**Files:**

- [ ] **Step 2: Write the `Dockerfile`**

```dockerfile
# The Energiewende agent API.
FROM python:3.12-slim

WORKDIR /app
ENV PYTHONUNBUFFERED=1 \
    PIP_NO_CACHE_DIR=1 \
    HF_HOME=/app/hf_cache \
    PYTHONPATH=/app/src

# Packages first, so Docker can reuse this layer when only the code changes.
# PyTorch from the CPU-only index: no GPU libraries, a much smaller image.
COPY requirements.txt .
RUN pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cpu \
    && pip install -r requirements.txt

# Download the embedding model at build time, so the container works offline.
RUN python -c "from sentence_transformers import SentenceTransformer; SentenceTransformer('intfloat/multilingual-e5-small')"
ENV HF_HUB_OFFLINE=1

COPY src/ src/

# The search index is not in the image. Mount it: -v ./data:/app/data
EXPOSE 8000
HEALTHCHECK --interval=30s --timeout=5s \
    CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:8000/health')"
CMD ["uvicorn", "energiewende.api.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

- [ ] **Step 3: Build it**

Run: `docker build -t energiewende-agent .`
Expected: the build finishes (see the verified facts for time and size).

- [ ] **Step 4: Run it and ask a question**

### Task 3: Docker Compose with MLflow

**Files:**
- Create: `docker-compose.yml`

- [ ] **Step 1: Write `docker-compose.yml`**

```yaml
# Start everything:  docker compose up -d
#   API:     http://localhost:8000/docs
#   MLflow:  http://localhost:5000
services:
  app:
    build: .
    ports:
      - "8000:8000"
    env_file: .env
    volumes:
      - ./data:/app/data  # search index and API cache, built by scripts/build_index.py

  mlflow:
    image: ghcr.io/mlflow/mlflow:v3.16.1
    ports:
      - "5000:5000"
    # The evaluation runs store absolute paths to ./mlruns, so we mount it at the same path.
    working_dir: ${PWD}
    volumes:
      - ./mlflow.db:${PWD}/mlflow.db
      - ./mlruns:${PWD}/mlruns
    command: mlflow server --host 0.0.0.0 --port 5000 --backend-store-uri sqlite:///mlflow.db
```

- [ ] **Step 2: Start it**

Run: `docker compose up -d --build && docker compose ps`
Expected: two services; `app` becomes `healthy` within about a minute.

### Task 4: GitHub Actions

**Files:**
- Create: `.github/workflows/ci.yml`

- [ ] **Step 1: Write the workflow**

```yaml
# Runs on every push and pull request: lint, tests, Docker build.
name: CI

on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-python@v7
        with:
          python-version: "3.12"
          cache: pip
      - name: Install packages (CPU-only PyTorch)
        run: |
          pip install torch==2.14.1 --index-url https://download.pytorch.org/whl/cpu
          pip install -r requirements-dev.txt
      - name: Lint
        run: ruff check .
      - name: Test
        run: pytest -q

  docker:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v7
      - name: Build the image
        run: docker build -t energiewende-agent .
```

- [ ] **Step 2: Push and watch**

```bash

```

Expected: both jobs green. If a job fails, read the log with `gh run view --log-failed`, fix the cause, and push again.
